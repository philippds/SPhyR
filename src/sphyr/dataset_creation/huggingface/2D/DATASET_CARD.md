# SPhyR — Spatial-Physical Reasoning on Material Distribution

SPhyR poses topology optimization problems as grid completion tasks. A model is
shown a 2D domain with applied loads (`L`), fixed supports (`S`) and masked
cells (`V`), and must predict the material distribution that carries the load
with the least material.

| Token | Meaning |
| --- | --- |
| `L` | applied load (solid by definition) |
| `S` | fixed support (solid by definition) |
| `V` | masked cell, to be predicted |
| `0`–`1` | material density (`0`/`1` on `easy`, one decimal place on `hard`) |

Historical records are `{"index": int, "input_grid": [[str]], "ground_truth": [[str]]}`.
Corrected `v2-force` and `v2-20-force` records also contain
`"load_direction": [row_component, column_component]`, the force used to generate
the layout. Positive row points down, positive column points right; the
simulator normalizes the vector. The prompt states it explicitly.

## Which version to use

**Use `v2-force` or `v2-20-force` for new work.** The historical versions remain
available to replay the paper's existing results.

| Version | Grid | Samples | Nearest-neighbour boundary-condition distance |
| --- | --- | --- | --- |
| `v1` | 10×10 | 1296 | **1 cell** (1294 of 1295 boundary conditions) |
| `v2` | 10×10 | 300 | ≥ 6 cells |
| `v2-20` | 20×20 | 300 | ≥ 6 cells |
| `v2-force` | 10×10 | 300 | ≥ 6 cells |
| `v2-20-force` | 20×20 | 300 | ≥ 6 cells |

The historical v2 tasks omitted generation force vectors. Their reported
single-step, sparse-format and feedback evaluations instead use a fixed
downward force, which the prompts leave implicit. Stored layouts provide
visible cells, reconstruction targets and budgets, without a claim that those
layouts are optimal for the evaluated force. The scoring optimizer and the
completion are simulated under the same evaluated force. Those results do not
measure reasoning over explicitly specified force directions.

The corrected versions preserve all historical grids and masks and add the
recovered generation force. Recovery replayed seed 0 and verified every one of
the 600 load cases by reproducing both its binary and rounded density answers.
`provenance.json` records verification and source-file hashes. Corrected tasks
require fresh model replies; no corrected-task model results are reported.

### Why v2 exists

`v1` was generated by sweeping load and support positions one cell at a time
along two fixed edges. Among the 1296 samples of a subject there are 1295
distinct boundary conditions, each mapping to exactly one ground-truth
structure, and for 1294 of them the nearest *different* boundary condition is a
single cell away. Adjacent load cases therefore usually share an optimal
structure, so the dataset is a dense sweep of a small space rather than a sample
of a large one, and a high score does not by itself indicate reasoning about
forces.

`v1`'s `full` variant compounds this: nominally a whole-structure prediction, it
masks only rows 1–8, leaving the entire load and support rows — 20 of 100 cells
— visible.

### What v2 changes

Sampling covers a broader layout family. Corrected records additionally
preserve the force vector so generation, prompting and evaluation agree.

- Loads and supports on **any edge in any combination**, supports optionally in
  two disjoint groups. v1 was always load-top, support-bottom.
- **Eight generation load directions** including diagonals, retained and stated
  explicitly only in the corrected `*-force` versions.
- **Rejection sampling**: a candidate is accepted only if its boundary condition
  differs from every accepted sample by ≥ 6 cells *and* its solved structure by
  ≥ 8 cells.
- **`full` masks every non-structural cell**, so the prediction is made from the
  load and support cells alone.
- Ground truth from the project's own SIMP optimizer, so the dataset
  **regenerates from source**.

### Grid sizes

`v2` ships at 10×10 for continuity and at 20×20, where the design space admits
multi-member trusses rather than a single load path. Variant sizes scale with
the grid — cell counts by area, row and column counts by side length — so
`5_random_cell` masks 5% of the grid at either size:

| Variant | 10×10 | 20×20 | Masked |
| --- | --- | --- | --- |
| `1_random_cell` | 1 cell | 4 cells | 1% |
| `5_random_cell` | 5 cells | 20 cells | 5% |
| `10_random_cell` | 10 cells | 40 cells | 10% |
| `1_random_row` / `_column` | 1 line | 2 lines | ~10% |
| `3_random_row` / `_column` | 3 lines | 6 lines | ~29% |
| `full` | all free cells | all free cells | ~98% |

## Subjects

Eight task variations × two difficulties (`easy` = binary occupancy, `hard` =
continuous density), 16 subjects in total.

## Reproducing the published results

The published `v1` results **cannot** be reproduced by re-deriving samples from
this dataset. The masks for the fourteen randomly-masked subjects were drawn
once and are not regenerated deterministically; only the two `full` subjects,
whose masking is deterministic, reproduce exactly.

The samples that were actually evaluated are stored with every completion in
the results files of the code repository, and the evaluation harness replays
them directly, so a new model can be measured on precisely the samples the
published columns were measured on.

## Generating the dataset

```bash
python -c "from sphyr.dataset_creation.generate_v2 import generate_samples, write_subjects; \
           write_subjects(generate_samples(300, grid=20), 'new_datasets_v2_20_force')"
```
